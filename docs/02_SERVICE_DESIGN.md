# 02 · 服务设计：新人 × 同事 × HR 三方体验

## 1. 服务主张

> **Uniplay 教你公司的知识，Teamdex 教你公司里的人。**

Teamdex 不是一个"新人 App"，而是一个**三方服务**：HR 负责设定舞台和分发任务，同事是被认识、也在认识新人的一方，新人在游戏的推动下完成真实的线下连接。App 只是入口，服务真正发生在办公室里。

## 2. 设计原则

| 原则 | 含义 | 在产品里的体现 |
|---|---|---|
| **给开口一个理由** | 降低新人主动发起对话的心理门槛 | "我在做入职任务"成为开场白；每张卡附开场白建议 |
| **聊天是被认可的工作** | 同事配合是公司流程的一部分，不是私人打扰 | HR 发起、同事被标记为"关键同事"并附原因 |
| **双向，而不是单向打扰** | 新人认识同事，同事也认识新人 | 扫码即交换，同事获得新人卡与通知 |
| **只有当面才能解锁** | 真正的学习来自对话，而不是扫码本身 | fun fact 答案只能当面问出来 |
| **同事成本极低** | 参与越轻，参与率越高 | 2 分钟设置，之后只需亮出二维码 |
| **不制造比较** | 融入不是比赛 | 无排行榜；HR 看进度，不看"谁最受欢迎" |
| **信息由本人掌控** | 同事决定展示什么，随时可隐藏 | 编辑与隐藏卡片；私人笔记只有本人可见 |

## 3. 三方价值交换

| 角色 | 付出 | 获得 |
|---|---|---|
| 新人 | 主动去找人、当面聊天 | 开口的理由与开场白、清楚知道谁负责什么、第一周就有归属感 |
| 同事 | 2 分钟设置卡片、每次几分钟对话 | 知道谁是新人、被认可的"导师"角色、更顺畅的跨部门协作 |
| HR | 录入团队、为新人配置关键同事 | 可见的融入进度、可规模化的入职流程、可向管理层汇报的成效数据 |

## 4. 服务蓝图

服务分为 6 个阶段。每个阶段按五条泳道描述：新人、同事、HR 的前台行为，系统触点，以及后台支持。

### 阶段 0 · 录用确定（入职前 7 天）

| 泳道 | 内容 |
|---|---|
| HR 前台 | 在控制台添加新人（姓名、职位、入职日），勾选 5 位关键同事并写明原因 |
| 同事前台 | 收到通知："Yunfei starts Monday. You're one of 5 people they'll meet first." |
| 新人前台 | 暂无 |
| 触点 | HR 控制台"新建入职任务"；同事首页通知 |
| 后台 | 创建 quest 与 quest_targets；生成新人卡与邀请链接 |
| 情绪 | HR：希望这次入职不再靠运气 |

### 阶段 1 · 同事领卡（入职前 5 天）

| 泳道 | 内容 |
|---|---|
| 同事前台 | 打开"Claim your card"链接，2 分钟内设置头像、找我聊什么、fun fact 问题与答案 |
| HR 前台 | 在控制台看到卡片完成率，给未完成的同事发提醒 |
| 触点 | 卡片编辑页（实时预览卡片效果） |
| 后台 | 保存档案；fun fact 答案单独加密存放，前端不可读 |
| 痛点与机会 | 同事嫌麻烦 → 把设置做成"捏自己的像素小人"，本身就好玩 |

### 阶段 2 · 入职前预热（入职前 1–3 天）

| 泳道 | 内容 |
|---|---|
| 新人前台 | 收到邀请链接，看到自己的 Teamdex：5 张关键同事卡是灰色剪影，但能看到脸、名字、职位和"为什么要认识他" |
| 触点 | 新人收藏页（未收集状态） |
| 情绪 | 新人：从"我谁都不认识"变成"我至少知道要先见这 5 个人" |
| 设计意图 | **见面之前先认识**，这是对社恐新人最有效的减压 |

### 阶段 3 · 第一天与第一周（核心体验）

| 泳道 | 内容 |
|---|---|
| 新人前台 | 走到同事工位 → "Hi, I'm doing my Teamdex quest!" → 扫码 → 卡片揭晓 → 按开场白聊天 → 问出 fun fact 并解锁 → 在卡背写下第一印象 |
| 同事前台 | 亮出手机上的卡片二维码 → 收到 "Yunfei collected your card"，获得新人卡 → 回答 fun fact 问题 |
| HR 前台 | 在动态流看到实时进展；发现某位新人两天没有动静时主动关心 |
| 触点 | 扫码揭晓页、卡片详情、同事通知、HR 动态流 |
| 后台 | collect_card 函数创建双向连接并记录事件；unlock_fact 函数校验答案 |
| 情绪曲线 | 新人：紧张 → 扫码瞬间的惊喜 → 解锁 fun fact 的成就感 |
| 痛点与机会 | 同事不在工位 → 显示"Open to chat"状态，引导新人换个时间；同事没领卡 → 新人看到"Card coming soon"，HR 收到提醒 |

### 阶段 4 · 学习检验

| 泳道 | 内容 |
|---|---|
| 新人前台 | 收集 3 张以上后，做"Who do I ask?"小测验 |
| 触点 | 测验页、结果页 |
| 设计意图 | 把"认识人"转化为可检验的工作能力：知道问题该找谁 |

### 阶段 5 · Onboarding party（集齐关键同事）

| 泳道 | 内容 |
|---|---|
| 新人前台 | 像素小人跳舞的庆祝画面；fika 邀请自动发给 5 位关键同事 |
| 同事前台 | 收到 party 邀请 |
| HR 前台 | 看到该新人状态变为 Complete |
| 触点 | Party 页、同事通知 |
| 情绪 | 新人：第一周以被欢迎的感觉结束，而不是"终于熬过去了" |

### 阶段 6 · 回顾与成效（第 5 天之后）

| 泳道 | 内容 |
|---|---|
| 新人前台 | 回答一题自评："I know who to ask for help" |
| HR 前台 | 在成效看板看到：首次对话时间、fun fact 解锁率、测验正确率、自评前后变化 |
| 后台 | 聚合事件与连接数据 |
| 设计意图 | 让 HR 能向管理层证明"融入"是可衡量的 |

## 5. 关键时刻（Moments that matter）

1. **第一次看到关键同事的脸**（阶段 2）：焦虑开始下降的时刻。
2. **扫码翻卡的一秒**（阶段 3）：整个服务的情绪高点，动效必须做到最好。
3. **同事收到"你被收集了"**（阶段 3）：同事从旁观者变成参与者的时刻。
4. **fun fact 解锁**（阶段 3）：从"交换信息"变成"真正的对话"的时刻。
5. **像素派对**（阶段 5）：第一周的情绪收尾，也是 pitch 的高潮画面。

## 6. HR 端：分发与成效

HR 在这个服务里有两项职责：**分发**（让正确的人在正确的时间收到正确的任务）和**看见成效**。

### 分发

| 分发什么 | 发给谁 | 何时 | 渠道（本版） |
|---|---|---|---|
| 领卡邀请 | 全体同事 | 首次上线时 | 控制台生成链接，可复制 |
| 关键同事通知 | 被选中的 5 位同事 | 创建入职任务时 | App 内通知 |
| 新人邀请 | 新人 | 入职前 1–3 天 | 邀请链接与二维码 |
| Party 邀请 | 关键同事 | 新人集齐时 | App 内通知（自动） |

### 成效看板

| 指标 | 回答的问题 |
|---|---|
| 同事卡片完成率 | 团队是否准备好迎接新人？ |
| 首次收集时间 | 新人多快迈出第一步？ |
| 关键同事收集进度 | 新人是否在认识对的人？ |
| fun fact 解锁率 | 是真的聊了，还是只扫了码？ |
| 测验正确率 | 新人是否知道该找谁？ |
| 自评变化（第 1 天 vs 第 5 天） | 新人自己是否感到更有把握？ |

## 7. 隐私与伦理

- **同事自愿**：卡片内容由同事本人填写，可随时隐藏。未领卡的同事以"Card coming soon"显示，不强制。
- **私人笔记只属于新人**：第一印象等笔记只有写的人可见，HR 与被写的同事都看不到。
- **不做排名**：不显示"谁被收集最多"的排行，避免同事之间的人气比较；"导师"勋章只有本人可见。
- **最少数据**：只存储工作相关信息与本人同意展示的 fun fact。
- **GDPR**：在瑞典使用需说明用途、提供删除入口（P2：正式版本实现）。
